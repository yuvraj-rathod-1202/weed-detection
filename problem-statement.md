**AI-Based Weed Localization for Precision Laser Weeding**

# **1\. Problem Statement**

**Problem:** Develop an AI/ML system that finds individual weeds in agricultural field images and outputs **one exact target point per weed**, which an automated laser weeding machine can fire at to destroy the weed without harming nearby crops.

**Why useful:** Point-precise weed removal reduces herbicide use and manual labour, and enables targeted operation of autonomous farm machines.

# **2\. Goal of the Project**

* Input: an RGB image captured from an agricultural field.
* Output: for every weed, one laser target point (x, y) in image pixels, plus the weed's instance mask.
* Primary goal: compare deep learning models and point-extraction methods for laser weed targeting.
* Main hypothesis: models trained on commonly used non-Indian datasets do not perform equally well on Indian agricultural imagery (different crops, weed species, soil, lighting and cameras).
* Research objective: identify the model + point-extraction combination with the best targeting accuracy / speed trade-off, especially for Indian field conditions.
* Phase 2 (only if time permits): develop a custom model or approach based on the comparison results.

# **3\. Why Bounding Boxes Are Not Enough**

A laser needs a single point. The centre of a bounding box is a poor target: for irregular or elongated weeds it can fall on bare soil, and when plants overlap it can fall on a neighbouring crop.

| Aspect | Bounding box → box centre | Instance mask → point from mask |
| :---- | :---- | :---- |
| Weed shape | Rectangle, includes soil and neighbouring plants | Exact weed pixels |
| Target point | Box centre, can lie outside the weed | Computed from weed pixels only; can be guaranteed inside the weed |
| Overlapping crop | Crop pixels inside the box affect the point | Crop pixels are excluded |
| Cost | Fastest | Slightly slower (mask head + post-processing) |

# **4\. Approach: Instance Segmentation + Morphological Point Extraction**

1. **Instance segmentation.** A single-stage model (YOLO-seg family, e.g. YOLOv8-seg / YOLO11-seg) predicts a pixel-level mask for every weed, at real-time speed on edge hardware.
2. **Single-point extraction.** Lightweight post-processing turns each mask into one target point:

| Method | Point | Property |
| :---- | :---- | :---- |
| Distance transform | Mask pixel farthest from the mask border | Always inside the weed; maximal safety margin; may pick the widest leaf rather than the stem |
| Skeleton | Skeleton pixel closest to the mask centroid | Inside the weed; approximates the stem / plant centre |
| Centroid | Centre of mass of the mask | Fast; can fall outside non-convex weeds |
| Box centre (reference) | Centre of the mask's bounding box | What a box-only detector would aim at |

3. **Ground-truth masks.** The main dataset (CottonWeedDet12) has bounding boxes only. GT instance masks are generated by prompting the Segment Anything Model (SAM 2.1) with each GT box. These are pseudo-labels and are inspected visually before training.

# **5\. Models to Compare**

| Model | Type | Status / why include it |
| :---- | :---- | :---- |
| YOLO11n-seg | Single-stage instance segmentation | **Baseline (implemented)**; smallest and fastest, edge-deployable |
| YOLO11s/m-seg | Single-stage instance segmentation | Accuracy vs. speed scaling of the baseline |
| YOLOv8-seg | Single-stage instance segmentation | Most widely used in weed-segmentation literature |
| Mask R-CNN | Two-stage instance segmentation | Established accuracy-oriented reference |
| CPD-WeedNet | Weed-specific instance segmentation | Candidate from the literature, to be verified |

Semantic segmentation models (U-Net, DeepLabV3+) are not primary candidates: they do not separate touching weeds into instances, so one point per weed cannot be derived reliably.

The final list can be reduced if compute is limited.

# **8\. Evaluation Objectives and Metrics**

| Objective | Metrics | Why important |
| :---- | :---- | :---- |
| Segmentation quality | Mask mAP@50, mAP@50:95, precision, recall (box metrics also reported) | Standard instance-segmentation performance |
| Targeting precision | **Shot precision**: fraction of fired points inside a GT weed mask | A point off the weed wastes a shot or hits a crop |
| Targeting recall | **Weed hit rate**: fraction of GT weeds receiving at least one point | A missed weed stays in the field |
| Point accuracy | **Point error** (px, and relative to weed radius) between predicted and GT point | How precisely the laser is aimed |
| Inference speed | Latency per image (model + point extraction), FPS | Real-time operation on a moving machine |
| Computational cost | Parameters, GFLOPs, memory | Edge/robot deployment |
| Model size | Weights file size | Embedded deployment |
| Robustness | Performance across lighting, field, season, weed density | Real-world generalisation |
| Cross-domain generalisation | Indian test performance after training on non-Indian data | Tests the main hypothesis |
| Indian-domain performance | Performance on a held-out Indian test set | Main research objective |

The final choice uses the trade-off between targeting accuracy, missed and false shots, latency and compute, not a single metric.

# **9\. Limitations to Report**

* GT masks are SAM pseudo-labels, not manual annotations.
* The GT target point is derived from the GT mask with the same method; there is no manually annotated stem position.
* CottonWeedDet12 has no crop annotations, so shot precision counts every off-weed shot as a miss; it cannot separate soil hits from crop hits.
* The split is a random image-level split (65/20/15, seed 42); near-identical frames from one field session can appear in different splits.
